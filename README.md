# Pac-Man

## Description

A remake of the 1980 arcade game **Pac-Man**, written in Python with
[pygame-ce](https://pyga.me/).

Guide Pac-Man through a maze, eat every pacgum and avoid the four ghosts
(Blinky, Pinky, Inky and Clyde). Eat a super-pacgum to make the ghosts
edible for a few seconds. Clear all the levels to win the game.

Main features:

- 10 levels by default, each with its own maze size and time limit.
- Mazes generated by an external **A-Maze-ing** package (not written by us).
- Four ghosts with their own chase behavior, based on the original arcade AI.
- A persistent **top 10 highscore** table.
- A JSON configuration file with comments, which tolerates errors.
- Main menu, instructions screen, pause menu, and a game over / victory screen.
- A cheat mode for the peer review.

## Instructions

### Requirements

- Python 3.10 or later
- [uv](https://docs.astral.sh/uv/)

### Installation and launch

```bash
make install          # install the dependencies (uv sync)
make run              # launch the game with config.json
```

You can also launch the game directly. It takes **exactly one argument**, the
configuration file:

```bash
uv run python pacman.py config.json
```

If the argument is missing, or the file does not exist or is not valid JSON,
the game prints a clear error message and exits with status 1.

### Other Makefile rules

| Rule | Action |
|---|---|
| `make clean` | Remove `__pycache__`, `.mypy_cache` and `.pytest_cache` |
| `make lint` | Run `flake8` and `mypy` with the flags required by the subject |
| `make lint-strict` | Run `flake8` and `mypy --strict` |

To run the game in the Python debugger:

```bash
uv run python -m pdb pacman.py config.json
```

### Controls

| Key | Action |
|---|---|
| Arrow keys | Move Pac-Man |
| `ESC` | Pause / resume |
| `M` (in pause) | Back to the main menu |
| `Enter` / `Space` | Select a menu entry |
| `ESC` (scoreboard, instructions, end screen) | Back to the main menu |

### Rules

- Pac-Man starts with 3 lives in the middle of the maze.
- Pacgums give 10 points and super-pacgums give 50 points.
- A super-pacgum makes the ghosts edible for 8 seconds. An eaten ghost gives
  200 points and comes back to its corner 5 seconds later.
- Touching a ghost costs a life, and Pac-Man respawns in the middle of the maze.
  He cannot be touched for 2 seconds after a respawn.
- A level is cleared when every pacgum is eaten. Score and lives are kept
  from one level to the next.
- **If the time limit of a level is reached, the game is over.**
- The game ends when all levels are cleared (victory) or when all lives are
  lost (game over). The player then enters a name to save the score.

### Cheat mode

| Key | Action |
|---|---|
| `C` | Enable cheat mode (required for the keys below) |
| `L` | Toggle invincibility (no life lost when touched by a ghost) |
| `W` | Skip the current level (after the last level, the game is won) |

## Configuration

The configuration is a JSON file. Lines starting with `#` (even indented) are
comments and are ignored.

```json
# Example configuration
{
	"levels": [
		{ "id": 1, "width": 20, "height": 20, "max_time": 500, "seed": 42 },
		{ "id": 2, "width": 17, "height": 17, "max_time": 150 }
	],
	"lives": 3,
	"points_per": {
		"pacgum": 10,
		"super_pacgum": 50,
		"ghost": 200
	}
}
```

| Key | Type | Default | Allowed values |
|---|---|---|---|
| `levels` | list of objects | one level with the default values | non-empty list |
| `levels[].id` | int | position in the list | ≥ 0 |
| `levels[].width` | int | 15 | 3 to 60 |
| `levels[].height` | int | 15 | 3 to 60 |
| `levels[].max_time` | int (seconds) | 120 | ≥ 1 |
| `levels[].seed` | int | **42 for the first level**, 0 for the others | ≥ 0 (0 = random maze) |
| `lives` | int | 3 | ≥ 1 |
| `points_per.pacgum` | int | 10 | ≥ 0 |
| `points_per.super_pacgum` | int | 50 | ≥ 0 |
| `points_per.ghost` | int | 200 | ≥ 0 |

### Faulty configuration

- **Missing or invalid value**: the default value is used, or the value is
  clamped to the allowed range. A message is printed, for example
  `config: level #1: 'width' 9999 clamped to 60`, and the game goes on.
- **Unknown keys** are ignored.
- **Missing file, unreadable file or invalid JSON**: the game prints an error
  and exits with status 1. It never shows a Python traceback.

## Highscore

Scores are stored in `scores.json` at the root of the project, as a JSON
object that maps each player name to their score:

```json
{
  "Alice": 1250,
  "Bob": 430
}
```

- Scores are loaded when the game starts and saved at the end of each game
  (victory or game over), after the player enters their name.
- Only the **top 10** scores are kept. They are shown in the **Score Board**
  menu entry and on the end screen.
- A name has **at most 10 characters**, made of ASCII letters, digits and
  spaces only. Other characters are ignored while typing. An empty name is
  saved as `player`.
- Scores are non-negative integers.
- **If a player uses a name that is already in the table, their new score
  replaces the old one**, even if it is lower. Each name appears only once.
- **File errors**: if the file is missing, unreadable, not valid JSON or not a
  JSON object, the game starts with an empty table. Invalid entries are
  ignored. If the file cannot be written, the scores are kept for the current
  session only.

**Why this design?** A JSON file is readable, can be edited by hand for tests,
needs no dependency, and is enough for 10 entries. Using the name as key makes
the "one score per player" rule simple. Every name and score is checked with a
pydantic model (`Score`), both when reading the file and when saving.

## Maze Generation

Mazes are generated by the A-Maze-ing package that was assigned to us
(`mazegenerator-2.1.0-py3-none-any.whl`, installed as is by `uv sync`). We do
not modify it.

```python
MazeGenerator(size=(width, height), perfect=False, seed=seed)
```

- `perfect=False` removes the dead ends, which gives Pac-Man-like corridors
  with loops.
- `seed`: the first level uses a fixed seed (42 by default) so its maze is
  always the same. The other levels use seed `0`, which gives a random maze.
- The package returns `maze.maze`, a grid of integers. Each cell stores its
  walls as bits: `1` = north, `2` = east, `4` = south, `8` = west. A cell
  equal to `15` is fully closed: these cells draw the "42" pattern in the
  middle of the maze. They are drawn as solid blocks and have no pacgum.
- Our loader adapts to this format: Pac-Man and the ghosts can move from a
  cell to its neighbor only if the wall bit is not set.
- If the generator raises an error, the game prints a clear message and exits
  with status 1.

From this grid, the game places:

- a pacgum on every free cell,
- a super-pacgum in each of the 4 corners,
- a ghost in each of the 4 corners,
- Pac-Man on the free cell closest to the center (the exact center is often
  part of the "42" pattern).

## Implementation

- **Scene-based game loop**: `Engine` runs the loop at 60 FPS. Each frame, it
  sends the events to the current scene, then calls `update(dt)` and
  `draw(surface)`. Scene changes are applied at the end of the frame.
- **Grid movement with interpolation**: Pac-Man and the ghosts move from cell
  to cell. A `progress` value from 0 to 1 is used to draw them smoothly
  between two cells. Pac-Man moves at 6 cells per second, ghosts at 4.5, and
  frightened ghosts at 2.5. The next direction is buffered, so the player can
  press a turn before reaching an intersection.
- **Ghost AI** (inspired by the original arcade game):
  - A `WaveManager` alternates the ghosts between *scatter* and *chase*
    phases (7 s / 20 s, then 5 s / 20 s, then chase only).
  - In *scatter*, the ghosts wander randomly.
  - In *chase*, each ghost aims at its own target cell: **Blinky** aims at
    Pac-Man, **Pinky** at 4 cells in front of Pac-Man, **Inky** at a point
    computed from Blinky's position and Pac-Man's, and **Clyde** chases
    Pac-Man when he is far away and goes back to his corner when close.
  - At each new cell, a ghost picks the open direction that brings it
    closest to its target. It never turns back, except in a dead end.
  - In *frightened* mode (after a super-pacgum), the ghosts turn around and
    pick the direction that takes them farthest from Pac-Man.
- **Configuration parsing**: comment lines are removed before `json.loads`.
  Each value is checked by `Engine._get_int` (type and range), then stored in
  pydantic models (`Config`, `LevelConfig`, `PointsConfig`).
- **Error handling**: configuration, maze generation and asset errors are
  caught in `pacman.py`, which prints a clear message and exits with status
  1. Paths to assets and to `scores.json` are absolute (based on the project
  root, or on the PyInstaller folder when packaged), so the game can be
  launched from any directory.

## General Software Architecture

```
pacman/
├── pacman.py                  # Entry point: arguments, error handling
├── config.json                # Default configuration
├── scores.json                # Highscores
├── pacman.spec                # PyInstaller packaging spec
├── Makefile
├── pyproject.toml / uv.lock   # Dependencies (uv)
├── mazegenerator-2.1.0-py3-none-any.whl   # Assigned A-Maze-ing package
├── project_management/        # Project management documents
└── src/
    ├── utils.py               # get_resource_path: absolute asset paths
    ├── models/
    │   ├── models.py          # Config, LevelConfig, PointsConfig, PacManConfig
    │   └── scoreboard_models.py   # Score (name and score validation)
    ├── engine/
    │   ├── engine.py          # Engine: window, game loop, config loading
    │   ├── wave_manager.py    # WaveManager: scatter / chase phases
    │   └── scenes/
    │       ├── scene_baseclass.py    # Scene (abstract base class)
    │       ├── scene_menu.py         # MenuScene: main menu
    │       ├── scene_running.py      # RunningScene: the game itself
    │       ├── scene_pause.py        # PauseScene
    │       ├── scene_gameover.py     # GameOverScene: victory / game over, name input
    │       ├── scene_scoreboard.py   # ScoreBoard: top 10, load / save
    │       └── scene_instructions.py # InstructionsScene: controls and rules
    ├── sprites/
    │   ├── base.py            # GameObject, Sprite (base classes)
    │   ├── pacman.py          # PacMan
    │   ├── ghost.py           # Ghost, GhostState
    │   ├── sprites.py         # Blinky, Pinky, Inky, Clyde
    │   └── items.py           # PacGum, SuperPacGum
    └── assets/                # Images and font
```

### Relationships

- `Main` (`pacman.py`) creates the `Engine` and catches fatal errors.
- `Engine` loads the `Config`, owns the window and the `WaveManager`, and
  creates **one instance of each scene**. Scenes switch between each other
  with `engine.change_scene(...)`.
- Every scene inherits from `Scene` and implements `handle_event`, `update`
  and `draw`.
- `RunningScene` builds the maze with `MazeGenerator`, and owns the `PacMan`,
  the four ghosts and the grid of `PacGum` / `SuperPacGum`. At the end of the
  game, it sends the final score to `GameOverScene`.
- `GameOverScene` asks for the player's name and saves the `Score` through
  `ScoreBoard`, which reads and writes `scores.json`.
- `PacMan` and `Ghost` inherit from `Sprite`. `Blinky`, `Pinky`, `Inky` and
  `Clyde` inherit from `Ghost` and override `update_target` with their own
  chase target. `PacGum` and `SuperPacGum` inherit from `GameObject`.
